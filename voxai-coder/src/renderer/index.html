Account
Your OpenRouter keys. Stored in the OS keychain when available and only ever sent to OpenRouter.

      

        
OpenRouter key
Every model call and web search is billed to this key.
not set
Management key optional
Adds your full account usage history. Not needed to run the agent.
not set
Keys are saved only when you press Save keys.

        
Balance
Read from OpenRouter when the app starts and after each run.
—
Usage history
Per-model spend on this key.

        
Updates
Checks for new versions shortly after the app starts, every 30 minutes, and when you come back to the window.

      

    


    

      
Spending
A hard stop for each run, so a loop or a big fan-out can’t drain the account.

      

        
Limit per run
The run stops when it reaches this. Sub-agents and web searches draw from the same allowance.
USD
Limit per goal
A goal (/goal) keeps starting new runs until it is met. It pauses when all its runs together reach this.
USD
Quick picks
Typical runs on a DeepSeek Flash model cost under a cent.

      

    


    

      
Web search
Lets the agent find sources instead of guessing URLs. Each search is billed on top of model tokens.

      

        
Search the web
Off means the agent can only read pages it already has links to. Sub-agents follow this too.
Engine
OpenRouter’s fee for each search on that engine.
Results per search
What the agent gets back when it doesn’t ask for a number. Above 10, OpenRouter charges extra per result.

      

    


    

      
Sub-agents
Workers the agent can hand self-contained jobs to. They report back and share the run’s spending limit.

      

        
Model
A cheaper model makes fan-outs cheaper. Leave empty to use the session’s model.
Eyes for models that cannot see
When the session’s model cannot read images, this model looks at each screenshot and describes it, problems included. Empty turns it off.
Turns before answering
How many tool steps a worker may take before it must report.
turns
Time limit
A worker still running after this is stopped and returns what it has.
sec

      

    


    

      
Context
How much of the conversation is sent with each request. The defaults suit almost everyone.

      

        
Context size
Kept well under the model’s maximum so requests stay fast and cheap.
tokens
Summarise older turns at
When the conversation fills this much of the context, early turns are folded into a summary.
Always summarise at
A safety net: past this, summarising is forced before the next request is sent.
Longest tool output kept
Longer results keep their start and end, with the middle marked as cut.
chars

        
Each of these can also be set before launch with an environment variable: VOX_CONTEXT_LIMIT, VOX_COMPACT_THRESHOLD, VOX_HARD_LIMIT_FRACTION, VOX_TOOL_RESULT_MAX_CHARS.

      

    

    

      
Memory
What the agent has chosen to remember about this project. It reads these at the start of every run. Remove any that are wrong or out of date.

      

        

        

      

    

    

      
Skills
Instructions the agent loads when a task needs them: how to use a tool, a service or the preview browser. It sees each skill's one-line description at the start of every run and loads the whole skill when a task calls for it.

      

        

        

        
To add a skill, make a folder with a SKILL.md in your skills folder (for all projects) or in a project's .voxai/skills folder (for that project). Start the file with a name: and a one-line description: between --- lines; the description is what the agent reads to decide when to load it. Skills in Claude Code's and Codex's folders are read too.

      

    

    

      
Keyboard
Shortcuts that work anywhere in the window.
